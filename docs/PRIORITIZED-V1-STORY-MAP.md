# Prioritized v1 story map and Phase 0 exit review

**Task:** MN-PLAN-008 · **Plan phase:** Phase 0 — close planning and turn decisions into build contracts

**Status:** Planning artifact; product implementation is not authorized. Phase 0 remains **In progress**.
**Authority:** [`AGENTS.md`](../AGENTS.md), [`IMPLEMENTATION-PLAN.md`](IMPLEMENTATION-PLAN.md), approved entries in [`DECISION-REGISTER.md`](DECISION-REGISTER.md), and the linked canonical requirements.

## Purpose and boundaries

This map orders the v1 story backlog by prerequisite and risk, then links each slice to the existing route/action and acceptance catalog. It does not replace the phase sequence, invent estimates, choose vendors, settle open commercial/legal values, or authorize implementation. The phase numbers and exit gates in `IMPLEMENTATION-PLAN.md` remain authoritative. Work may overlap only after its prerequisites and interfaces are approved.

Prioritization uses four rules:

1. Establish isolated environments and security boundaries before feature workflows.
2. Establish tenant identity, branch scope, permissions, audit, and lifecycle before CRUD or financial access.
3. Build payment and network behavior behind their independent service boundaries before subscriber purchase-to-access journeys.
4. Keep external approvals, production readiness, and each country launch behind explicit evidence gates; do not represent targets or candidates as live.

No calendar estimates are assigned because team capacity, named owners, budget, provider access, and implementation start date are not set.
